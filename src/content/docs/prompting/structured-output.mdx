# {frontmatter.title}

By default, Claude wraps JSON in markdown code fences and adds explanatory prose. That's fine for chat — useless for programmatic consumption. This page covers three techniques for extracting clean, parseable structured data: assistant prefill with stop sequences, JSON output mode, and tool-use coercion.

## Technique 1: Prefill + Stop Sequence

Seed the assistant's response with an opening delimiter and stop generation at the closing one. Claude fills in only the structured content between them.

```python
import json
from anthropic import Anthropic

client = Anthropic()

message = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Generate an AWS EventBridge rule for EC2 instance state changes as JSON."},
        {"role": "assistant", "content": "```json\n"}
    ],
    stop_sequences=["```"]
)

raw = message.content[0].text
parsed = json.loads(raw.strip())
print(json.dumps(parsed, indent=2))
```

How it works:
1. The assistant message `"```json\n"` makes Claude think it already started a code block
2. Claude generates the JSON content
3. The stop sequence `"```"` halts generation at the closing fence
4. You get raw JSON — no fences, no commentary

Always call `.strip()` before parsing. The response typically has a leading newline.

This technique generalizes to any delimited format — swap `"```json\n"` / `"```"` for `"```python\n"` / `"```"` to extract Python code, or use `"<result>\n"` / `"</result>"` for XML-wrapped content.

:::warning
If Claude's output is malformed and never produces the closing delimiter, the stop sequence won't fire and generation continues until `max_tokens`. Check `message.stop_reason` — if it's `max_tokens` instead of `stop_sequence`, the output may be incomplete or invalid.
:::

## Technique 2: JSON Output Mode

The API supports a native `output_config.format` parameter that constrains Claude to produce valid JSON matching a schema you provide. No prefill hacking required.

```python
import json
from anthropic import Anthropic

client = Anthropic()

message = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Extract the key entities from this text: 'Apple announced the iPhone 16 at their Cupertino headquarters on September 9, 2024.'"}
    ],
    output_config={
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {
                    "entities": {
                        "type": "array",
                        "items": {
                            "type": "object",
                            "properties": {
                                "name": {"type": "string"},
                                "type": {"type": "string", "enum": ["PERSON", "ORG", "PRODUCT", "LOCATION", "DATE"]},
                            },
                            "required": ["name", "type"]
                        }
                    }
                },
                "required": ["entities"]
            }
        }
    }
)

result = json.loads(message.content[0].text)
print(json.dumps(result, indent=2))
```

Claude's output is guaranteed to conform to the provided JSON schema. This is the most reliable approach for structured extraction at scale.

## Technique 3: Tool-Use Coercion

Define a tool with the JSON schema you want, and force Claude to "call" it. The tool input is your structured data — you never actually execute the tool.

```python
import json
from anthropic import Anthropic

client = Anthropic()

message = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Extract: 'John Smith, age 34, works at Acme Corp as a senior engineer in Portland, OR.'"}
    ],
    tools=[{
        "name": "extract_person",
        "description": "Extracts structured person information from text.",
        "input_schema": {
            "type": "object",
            "properties": {
                "name": {"type": "string"},
                "age": {"type": "integer"},
                "company": {"type": "string"},
                "title": {"type": "string"},
                "location": {"type": "string"}
            },
            "required": ["name", "age", "company", "title", "location"]
        }
    }],
    tool_choice={"type": "tool", "name": "extract_person"}
)

# The structured data is in the tool call input
tool_input = message.content[0].input
print(json.dumps(tool_input, indent=2))
```

`tool_choice` with `type: "tool"` forces Claude to call the specified tool. The `input` field on the `tool_use` content block contains your structured data, already validated against the schema.

For more on tool use beyond structured output, see [Tool Use](/the-api/tool-use).

## Which Technique to Use

| Technique | Best For | Tradeoffs |
| --- | --- | --- |
| **Prefill + stop** | Quick prototyping, simple formats | No schema validation; output can be malformed |
| **JSON output mode** | Production structured extraction | Requires schema definition; cleanest approach |
| **Tool-use coercion** | Complex nested schemas, existing tool pipelines | Slightly more verbose setup; well-tested pattern |

For production systems, prefer JSON output mode or tool-use coercion. Both guarantee schema-conformant output. The prefill technique is faster to set up but requires you to handle parse failures yourself.

:::tip
Combine structured output with a [system prompt](/prompting/system-prompts) for best results. A system prompt like `"Extract information exactly as requested. Do not add commentary."` reduces the chance of Claude adding narrative text alongside structured data.
:::

## Parsing and Validation

Regardless of technique, always validate the output:

```python
import json
from typing import Any

def safe_parse(raw: str) -> dict[str, Any] | None:
    """Parse JSON with graceful failure."""
    try:
        return json.loads(raw.strip())
    except json.JSONDecodeError as e:
        print(f"Parse error: {e}")
        return None
```

For production pipelines, use Pydantic for schema validation after parsing:

```python
from pydantic import BaseModel

class Person(BaseModel):
    name: str
    age: int
    company: str
    title: str
    location: str

# Validates and converts types
person = Person.model_validate(tool_input)
```
