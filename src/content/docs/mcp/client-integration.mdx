An MCP client connects to one or more MCP servers, discovers their tools, and wires them into Claude conversations. This page covers client-side integration patterns — from single-server setups to multi-server coordination and Claude Code configuration.

The tool calling protocol is the same as [direct tool use](/the-api/tool-use) — `tool_use` blocks from Claude, `tool_result` blocks from you. MCP changes how tools are discovered and executed, not the protocol itself.

## Single-Server Client

The minimal client connects to one server, discovers tools, and runs an agentic loop. This is the same loop from [Tool Use: The Agentic Loop](/the-api/tool-use#the-agentic-loop), but tools come from `list_tools()` instead of a hardcoded list, and execution goes through `call_tool()` instead of a dispatcher function.

```python
import asyncio
import json
import anthropic
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def run(user_message: str) -> str:
    server = StdioServerParameters(command="python", args=["inventory_server.py"])

    async with stdio_client(server) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            # Discover tools (replaces hardcoded tool list)
            tools_result = await session.list_tools()
            tools = [
                {"name": t.name, "description": t.description, "input_schema": t.inputSchema}
                for t in tools_result.tools
            ]

            # Standard agentic loop — identical to direct tool use
            client = anthropic.Anthropic()
            messages = [{"role": "user", "content": user_message}]

            while True:
                response = client.messages.create(
                    model="claude-sonnet-4-20250514",
                    max_tokens=1024,
                    tools=tools,
                    messages=messages,
                )
                messages.append({"role": "assistant", "content": response.content})

                if response.stop_reason != "tool_use":
                    break

                # Execute via MCP (replaces if/else dispatcher)
                tool_results = []
                for block in response.content:
                    if block.type == "tool_use":
                        result = await session.call_tool(block.name, block.input)
                        tool_results.append({
                            "type": "tool_result",
                            "tool_use_id": block.id,
                            "content": str(result.content[0].text) if result.content else "",
                        })
                messages.append({"role": "user", "content": tool_results})

            return "\n".join(b.text for b in response.content if b.type == "text")

print(asyncio.run(run("Is WIDGET-001 in stock?")))
```

Two things changed from direct tool use:
1. **Discovery**: `session.list_tools()` replaces your hardcoded `tools` list
2. **Execution**: `session.call_tool(name, input)` replaces your `run_tool()` dispatcher

Everything else — the loop structure, `stop_reason` check, `tool_result` format — is identical.

## Multi-Server Coordination

Production apps often connect to multiple MCP servers. Each server provides tools for a different domain — one for databases, another for file operations, a third for APIs.

```python
from contextlib import AsyncExitStack

async def run_multi_server(user_message: str) -> str:
    servers = {
        "inventory": StdioServerParameters(command="python", args=["inventory_server.py"]),
        "analytics": StdioServerParameters(command="python", args=["analytics_server.py"]),
        "notifications": StdioServerParameters(command="python", args=["notify_server.py"]),
    }

    async with AsyncExitStack() as stack:
        sessions: dict[str, ClientSession] = {}
        all_tools = []
        tool_to_server: dict[str, str] = {}

        # Connect to all servers and collect tools
        for name, params in servers.items():
            read, write = await stack.enter_async_context(stdio_client(params))
            session = await stack.enter_async_context(ClientSession(read, write))
            await session.initialize()
            sessions[name] = session

            tools_result = await session.list_tools()
            for tool in tools_result.tools:
                all_tools.append({
                    "name": tool.name,
                    "description": tool.description,
                    "input_schema": tool.inputSchema,
                })
                tool_to_server[tool.name] = name

        # Agentic loop with multi-server dispatch
        client = anthropic.Anthropic()
        messages = [{"role": "user", "content": user_message}]

        while True:
            response = client.messages.create(
                model="claude-sonnet-4-20250514",
                max_tokens=1024,
                tools=all_tools,
                messages=messages,
            )
            messages.append({"role": "assistant", "content": response.content})

            if response.stop_reason != "tool_use":
                break

            tool_results = []
            for block in response.content:
                if block.type == "tool_use":
                    # Route to the correct server
                    server_name = tool_to_server[block.name]
                    result = await sessions[server_name].call_tool(block.name, block.input)
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block.id,
                        "content": str(result.content[0].text) if result.content else "",
                    })
            messages.append({"role": "user", "content": tool_results})

        return "\n".join(b.text for b in response.content if b.type == "text")
```

The key addition is `tool_to_server` — a mapping from tool name to server name. When Claude calls a tool, you look up which server owns it and route the `call_tool()` there.

<Callout type="warning">
Tool names must be unique across all connected servers. If two servers expose a tool with the same name, the second one silently shadows the first. Prefix tool names with the server domain if conflicts are possible (e.g., `inventory_check_stock`, `analytics_query_sales`).
</Callout>

## Resource Injection

Instead of having Claude discover and fetch data via tool calls, inject resource content directly into the conversation. This saves a round-trip and reduces token usage.

```python
from pydantic import AnyUrl

async def run_with_context(session: ClientSession, user_message: str) -> str:
    # Pre-fetch resource to inject as context
    products_result = await session.read_resource(AnyUrl("inventory://products"))
    products = products_result.contents[0].text

    # Include resource data in the system prompt
    system = f"""You are an inventory assistant.

Current product catalog:
{products}

Use the check_stock and update_stock tools to answer questions about inventory levels."""

    # Now Claude has context without needing a tool call
    tools_result = await session.list_tools()
    tools = [
        {"name": t.name, "description": t.description, "input_schema": t.inputSchema}
        for t in tools_result.tools
    ]

    client = anthropic.Anthropic()
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        system=system,
        tools=tools,
        messages=[{"role": "user", "content": user_message}],
    )
    return response.content[0].text
```

<Callout type="tip">
Use resources for **stable context** (product catalogs, configuration, schemas) and tools for **dynamic queries** (stock levels, order lookups). Resources are fetched once; tools are called on demand.
</Callout>

## Claude Code as MCP Client

Claude Code acts as an MCP client. You configure servers in your project's `.mcp.json` file, and Claude Code connects to them at startup.

### Configuration

Create `.mcp.json` in your project root:

```json
{
  "mcpServers": {
    "inventory": {
      "command": "python",
      "args": ["mcp_servers/inventory_server.py"],
      "env": {
        "DATABASE_URL": "postgresql://localhost:5432/inventory"
      }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

Each entry specifies the command to start the server, arguments, and optional environment variables. `${VAR}` syntax pulls from your shell environment.

### Using MCP tools in Claude Code

Once configured, Claude Code discovers tools from all connected servers. You can verify with:

```
> /mcp
```

This lists all connected servers and their tools. Claude Code then uses these tools alongside its built-in tools (`Read`, `Edit`, `Bash`, etc.) — no special syntax needed. Ask Claude Code to "check inventory for WIDGET-001" and it routes to your MCP server automatically.

### Pre-built servers

The MCP ecosystem has pre-built servers for common services:

| Server | Package | Tools provided |
| --- | --- | --- |
| GitHub | `@modelcontextprotocol/server-github` | Issues, PRs, repos, search |
| PostgreSQL | `@modelcontextprotocol/server-postgres` | Query, schema inspection |
| Filesystem | `@modelcontextprotocol/server-filesystem` | Read, write, search files |
| Slack | `@modelcontextprotocol/server-slack` | Messages, channels, users |

These work with Claude Code, the Claude desktop app, and any MCP-compatible client.

## TypeScript Client

The TypeScript SDK follows the same pattern:

```typescript
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
import Anthropic from "@anthropic-ai/sdk";

const transport = new StdioClientTransport({
  command: "node",
  args: ["inventory_server.js"],
});

const mcpClient = new Client({ name: "my-app", version: "1.0.0" });
await mcpClient.connect(transport);

// Discover tools
const { tools: mcpTools } = await mcpClient.listTools();
const tools = mcpTools.map((t) => ({
  name: t.name,
  description: t.description ?? "",
  input_schema: t.inputSchema,
}));

// Use with Anthropic SDK — same agentic loop as direct tool use
const anthropic = new Anthropic();
const response = await anthropic.messages.create({
  model: "claude-sonnet-4-20250514",
  max_tokens: 1024,
  tools,
  messages: [{ role: "user", content: "Is WIDGET-001 in stock?" }],
});
```

## From Direct Tools to MCP

If you have an existing app with [direct tool definitions](/the-api/tool-use), migrating to MCP is mechanical:

1. **Extract tool functions** into an MCP server file
2. **Add `@mcp.tool()` decorators** — delete the JSON schema dicts, let type hints generate them
3. **Replace your dispatcher** with `session.call_tool()`
4. **Replace your hardcoded tool list** with `session.list_tools()`

The Claude API calls stay the same. You're swapping how tools are defined and executed, not the conversation protocol.
